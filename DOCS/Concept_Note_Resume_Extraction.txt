1. Problem Statement
Resumes are produced in a wide variety of formats, layouts, and writing styles, making automated processing a significant challenge. Manual review of large volumes of resumes is time-consuming, inconsistent, and difficult to scale within recruitment workflows.
Existing keyword-search approaches and rule-based parsers fail to generalise across non-standard resume structures, breaking whenever layout conventions differ. There is a clear need for an intelligent, automated system that converts unstructured PDF resumes into a standardised, machine-readable format regardless of document layout or writing style.
2. Proposed Solution
This project delivers a cloud-hosted, API-accessible pipeline that accepts PDF resumes as input and returns structured JSON containing key candidate information. The system combines document parsing, text preprocessing, and a fine-tuned NLP model — all deployed on AWS and exposed via a FastAPI backend.
The end-to-end pipeline flows as follows:
PDF Resume  →  Text Extraction  →  Preprocessing  →  NLP Model (LoRA)  →  Structured JSON Output
3. System Components

AWS EC2

AWS S3
Optional storage layer for uploaded resume files and output records.

4. AI Component
The core intelligence of the system lies in a Transformer-based language model sourced from Hugging Face and fine-tuned on annotated resume data. To keep computational requirements manageable, Low-Rank Adaptation (LoRA) is applied — a parameter-efficient fine-tuning technique that trains only a small set of adapter weights rather than the full model parameters.
The model is trained to identify and classify entities including:
	•	Candidate name and personal contact details
	•	Technical and soft skills
	•	Educational qualifications and institutions
	•	Work experience and employment history

Model quality is assessed using standard information extraction metrics:
	•	Precision — the proportion of extracted entities that are correct
	•	Recall — the proportion of actual entities successfully identified
	•	F1-score — the harmonic mean of Precision and Recall
5. Cloud Architecture
The system is designed for cloud deployment from the ground up. The FastAPI application runs on an AWS EC2 instance and is accessible via HTTP requests. Users and automated systems interact with the service through a clean REST API, testable via Postman or any HTTP client.

AWS services used:
	•	AWS EC2 — Compute instance hosting the FastAPI backend server
	•	AWS S3 — Scalable object storage for resume files and outputs
	•	AWS IAM — Identity and access management for secure service interaction
	•	CloudWatch — Logging, monitoring, and alerting for the deployed application
