Who uses it
Students complete Part I before idea approval. Supervisors complete Part II after reviewing the proposal.
Submission rule
Ideas should be approved only when the problem is clear, the scope is realistic, the course mapping is genuine, the evaluation plan is measurable, and the team can demonstrate a working end-to-end deliverable.

1. Problem statement and target users
	•	What problem are you solving?
	•	Who are the target users or stakeholders?
	•	Why is this problem worth solving in this semester project?
Team response:
Many resumes are unstructured and vary widely in format, making it difficult to automatically extract useful information such as skills, education, and experience. This creates challenges for recruiters and automated hiring systems, especially when processing large volumes of resumes.
The target users are recruiters, HR systems, and companies that need a scalable solution to handle resume processing efficiently.
This problem is suitable for this project because it combines a clear cloud-based system design with a supporting Natural Language Processing (NLP) component. The cloud enables scalable deployment and remote access to the service, while the NLP model performs the information extraction. The system can be implemented and evaluated within the semester using available datasets and cloud infrastructure.


2. Project summary in plain language
	•	Describe the idea in 4–6 clear sentences without buzzwords.
	•	State what the system will do from the user’s point of view.
Team response:
The system will take a resume in PDF format as input and automatically extract important information such as name, skills, and education. The PDF will first be converted into text, then processed by an AI model.
The model will analyze the text and generate a structured JSON output containing the extracted information. Users will interact with the system through an API and receive results instantly.
The goal is to turn messy resume documents into clean, structured data that can be easily used.

8. Cloud and deployment plan
	•	State how the project will use cloud resources.
	•	Identify deployment targets, storage needs, monitoring/logging needs, and security considerations.
	•	Explain why the cloud contribution is meaningful, not decorative.
Team response:
 The project is designed with cloud deployment as a core component.
The system will be containerized using Docker and deployed on AWS. The FastAPI backend (including the trained model) will run on an EC2 instance, exposing a public API for resume processing.
Uploaded resumes can be stored in S3, while results are stored locally or in a lightweight database. The cloud enables remote access, scalability, and reliable system operation.
This ensures the cloud component is essential to system functionality, not just an add-on.

C. Team-type checks
CS-only teams
Must include a real software system with backend logic, APIs, persistence, modular architecture, Dockerization, and meaningful workflows. Reject ideas that are only a basic CRUD app or only a wrapper around external AI APIs.
AI-only teams
Must include a defined modeling or optimization problem, a baseline, measurable evaluation, experiments, and analysis. Reject ideas that are only prompt engineering, only a UI around a ready-made model, or only a literature survey.
Mixed teams
Must show three visible layers: product/system layer, AI or algorithm layer, and cloud/deployment layer. Reject ideas where one layer is only cosmetic or where the work split is clearly unbalanced.
Supervisor note
If the core idea is promising but too broad, use “Approve with conditions” and require a narrower MVP, clearer data plan, or simpler integration scope.
